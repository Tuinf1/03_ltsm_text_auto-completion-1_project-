# План выполнения проекта

## Цель проекта

Подготовить и сравнить три модели для предсказания следующего слова:

1. LSTM, обученную с нуля на WikiText-2.
2. GRU, обученную в тех же условиях.
3. Предобученную модель `distilgpt2`.

Основные критерии сравнения: качество предсказаний, размер модели и скорость работы. Итоговая цель — определить, какая модель лучше подходит для мобильного приложения.

## Этап 0. Подготовка окружения

1. Проверить версию Python.
2. Проверить наличие GPU и поддержку CUDA в PyTorch.
3. Установить необходимые библиотеки:
   - `torch`;
   - `datasets`;
   - `transformers`;
   - `pandas`;
   - `numpy`;
   - `matplotlib`;
   - `seaborn`;
   - `tqdm`.
4. Зафиксировать случайность с помощью `SEED = 42`.
5. Настроить автоматический выбор устройства: CUDA при наличии, иначе CPU.
6. Добавить два режима запуска:
   - `FAST_RUN = True` — быстрая локальная проверка;
   - `FAST_RUN = False` — полный итоговый эксперимент.

### Результат этапа

Окружение готово, библиотеки импортируются, устройство определено, результаты эксперимента можно воспроизвести.

## Этап 1. Загрузка и анализ WikiText-2

1. Загрузить датасет `wikitext-2-raw-v1`.
2. Проверить стандартное разделение:
   - `train` — обучение;
   - `validation` — контроль качества во время обучения;
   - `test` — финальная оценка.
3. Вывести несколько примеров текстов.
4. Удалить или пропустить пустые строки.
5. Посчитать основные статистики:
   - количество текстовых блоков;
   - количество слов;
   - среднюю и медианную длину текста;
   - минимальную и максимальную длину;
   - долю пустых строк.
6. Построить распределение длин текстов.

### Важное замечание

Строки WikiText-2 не всегда являются отдельными предложениями. Поэтому в анализе следует называть их текстовыми блоками, если предложения не выделяются отдельно.

### Результат этапа

Понятна структура данных, их объём и особенности, которые нужно учитывать при токенизации.

## Этап 2. Создание уменьшенных выборок

Перед полным обучением необходимо проверить весь код на небольшом объёме данных.

Создать:

- `train_small` — небольшую часть обучающей выборки;
- `validation_small` — небольшую часть валидационной выборки;
- `test_small` — небольшую часть тестовой выборки для проверки кода оценки.

Уменьшенные части должны выбираться воспроизводимо с `SEED = 42`.

Обе модели — LSTM и GRU — должны получать одинаковые данные. Нельзя обучать их на разных выборках, иначе сравнение будет некорректным.

### Задачи пробного запуска

- проверить построение словаря;
- проверить кодирование текстов;
- проверить сдвиг входа и таргета;
- убедиться, что обучение запускается;
- убедиться, что loss и perplexity считаются;
- проверить сохранение лучшей модели;
- проверить генерацию предсказаний;
- оценить требуемые время и память.

### Результат этапа

Полностью рабочий pipeline, который быстро выполняется локально. Результаты на маленькой выборке не используются для окончательных выводов о качестве моделей.

## Этап 3. Пословная токенизация

1. Разбить тексты на слова и знаки препинания.
2. Привести слова к нижнему регистру, если выбран такой вариант нормализации.
3. Построить словарь только по полной обучающей выборке `train`.
4. Добавить специальные токены:
   - `<unk>` — неизвестное или редкое слово;
   - `<eos>` — конец текстового блока.
5. Задать минимальную частоту слова, например `min_freq = 2`.
6. Заменить редкие и неизвестные слова на `<unk>`.
7. Закодировать `train`, `validation` и `test` индексами одного словаря.
8. Вывести:
   - размер словаря;
   - самые частые слова;
   - долю `<unk>` в каждой части данных;
   - пример исходного и закодированного текста.

### Правило против утечки данных

Словарь строится только по `train`. Данные из `validation` и `test` не должны влиять на словарь или обучение модели.

### Результат этапа

Все тексты преобразованы в последовательности числовых идентификаторов.

## Этап 4. Dataset и DataLoader

1. Объединить закодированные тексты в поток токенов, разделяя текстовые блоки токеном `<eos>`.
2. Разделить поток на последовательности фиксированной длины, например `seq_len = 32`.
3. Для каждого фрагмента сформировать:

```text
X: токены от 1-го до предпоследнего
Y: те же токены со сдвигом на одну позицию вправо
```

Пример:

```text
Исходный фрагмент: the cat sat on the mat
X:                the cat sat on the
Y:                cat sat on the mat
```

4. Создать `Dataset` для train, validation и test.
5. Создать `DataLoader`:
   - для train использовать перемешивание;
   - для validation и test перемешивание не требуется.
6. Проверить формы тензоров и правильность сдвига.

### Результат этапа

Получены готовые батчи входов и правильных следующих токенов.

## Этап 5. Реализация общей рекуррентной модели

Создать единый класс языковой модели, в котором можно выбрать LSTM или GRU.

Архитектура:

```text
Embedding → LSTM или GRU → Dropout → Linear
```

Стартовые параметры:

- `embedding_dim = 128`;
- `hidden_dim = 256`;
- `num_layers = 2`;
- `dropout = 0.2`;
- `seq_len = 32`;
- `batch_size = 64`.

Дополнительно реализовать:

- подсчёт числа обучаемых параметров;
- подсчёт примерного размера весов модели;
- корректную инициализацию скрытого состояния;
- перенос модели и батчей на выбранное устройство.

### Результат этапа

Один проверенный класс позволяет создавать LSTM и GRU с одинаковыми внешними условиями.

## Этап 6. Цикл обучения и оценки

1. Использовать `CrossEntropyLoss`.
2. Использовать оптимизатор Adam с начальным `lr = 0.001`.
3. После обратного распространения применять gradient clipping.
4. После каждой эпохи сохранять:
   - train loss;
   - validation loss;
   - train perplexity;
   - validation perplexity;
   - время эпохи.
5. Сохранять состояние модели с минимальным validation loss.
6. При необходимости использовать раннюю остановку, если validation loss несколько эпох не улучшается.
7. Построить графики loss и perplexity.

Perplexity вычисляется по средней кросс-энтропии:

```text
perplexity = exp(mean_loss)
```

Нельзя усреднять perplexity отдельных батчей. Сначала нужно получить средний loss по всем оцениваемым токенам, затем применить экспоненту.

### Результат этапа

Получен общий и корректный механизм обучения, который одинаково используется для LSTM и GRU.

## Этап 7. Пробное обучение LSTM и GRU

1. Обучить LSTM на `train_small`.
2. Проверить, что train loss уменьшается.
3. Проверить validation perplexity.
4. Получить несколько предсказаний.
5. Повторить те же действия для GRU.
6. Исправить найденные ошибки до полного запуска.

Если локальное обучение слишком медленное, сократить для отладки:

- количество последовательностей;
- размер модели;
- batch size;
- количество эпох.

После проверки вернуть полные настройки.

### Результат этапа

Подтверждено, что обе архитектуры обучаются и оцениваются без ошибок.

## Этап 8. Полное обучение LSTM и GRU

1. Установить `FAST_RUN = False`.
2. Обучить LSTM на полной обучающей выборке.
3. Сохранить лучшую LSTM по validation loss.
4. Обучить GRU на тех же данных и с теми же основными гиперпараметрами.
5. Сохранить лучшую GRU.
6. Для каждой модели измерить:
   - лучшую validation perplexity;
   - test perplexity;
   - число параметров;
   - размер весов;
   - среднее время эпохи;
   - время одного предсказания на CPU после прогрева.

Полное обучение при наличии GPU лучше выполнять на предоставленной виртуальной машине или в Google Colab. Локальный режим остаётся способом проверить код до использования GPU.

### Результат этапа

Получены итоговые результаты LSTM и GRU в одинаковых условиях.

## Этап 9. Оценка distilgpt2

1. Загрузить токенизатор и предобученную модель `distilgpt2`.
2. Перевести модель в режим оценки.
3. Использовать собственный BPE-токенизатор `distilgpt2`.
4. Вычислить perplexity на тестовом тексте с учётом максимального контекстного окна модели.
5. При разбиении длинного текста использовать скользящее окно и не учитывать повторно уже оценённые токены.
6. Измерить:
   - количество параметров;
   - размер модели;
   - скорость одного предсказания на CPU или GPU.
7. Получить предсказания на тех же текстовых контекстах, которые используются для LSTM и GRU.

### Ограничение сравнения

Абсолютные значения perplexity `distilgpt2` и рекуррентных моделей нельзя считать напрямую эквивалентными, потому что используются разные словари и способы токенизации. Это ограничение нужно явно указать в выводах.

### Результат этапа

Получена оценка качества, размера и скорости предобученного трансформера.

```text

i want to
the weather today is

```

Для каждого контекста показать:

- пять наиболее вероятных слов LSTM;

Для LSTM и GRU дополнительно можно посчитать top-1 и top-5 accuracy. Эти показатели будут вспомогательными, а основной метрикой останется perplexity.

## Этап 12. Выводы и рекомендация

В выводах нужно ответить на следующие вопросы:

1. Какая из рекуррентных моделей показала меньшую perplexity?
2. Насколько велика разница между LSTM и GRU?
3. Какая модель имеет меньше параметров?
4. Какая модель быстрее обучается и выполняет предсказание?
5. Насколько качественнее выглядят продолжения `distilgpt2`?
6. Оправдывает ли качество `distilgpt2` её большой размер?
7. Какая модель лучше подходит для локальной работы на смартфоне?
8. Когда вместо локальной модели следует использовать серверный трансформер?

Предварительная продуктовая логика:

- если LSTM заметно точнее GRU, можно выбрать LSTM;
- если качество близкое, но GRU меньше и быстрее, предпочтительнее GRU;
- если необходимо максимальное качество и допустим серверный inference, можно выбрать `distilgpt2` или более современную компактную предобученную модель;
- для мобильного использования стоит дополнительно рассмотреть динамическую квантизацию выбранной рекуррентной модели.

Окончательная рекомендация должна основываться на полученных измерениях, а не на предположениях.
